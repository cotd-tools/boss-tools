# 怪物钓点 · Creatures of the Deep 点位指南

基于 Vue 3 + TypeScript + Vite + Tailwind CSS 4 + shadcn-vue 的纯静态网页，适用于 Creatures of the Deep 社区点位查询。

## 名称与垂钓说明

站名为 **怪物钓点 / Monster Spots**。道具名称统一使用 **Monster Bait（怪物诱饵）**。玩家先通过地图确定停船位置，再对照实景图投饵；出现气泡后向冒泡处抛竿静候。诱饵用于辅助定位，并非必需。每日点位保留原版社区周期，作为参考使用。

## 本地运行

使用 Node.js 24 LTS。

```sh
npm ci
npm run dev
```

打开终端输出的本地地址。生产构建与预览：

```sh
npm test
npm run build
npm run preview
```

## 部署到 GitHub Pages

1. 将此目录的源代码（包括 `images/`、`package-lock.json`、`.github/`）上传到 GitHub 仓库；使用 `dev` 分支验证改动，`main` 分支发布网站。不要上传 `node_modules/` 和 `dist/`。
2. 在仓库 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**。
3. 合并代码到对应分支，或在 **Actions → Test and Deploy → Run workflow** 选择分支后手动运行。
4. 工作流成功后，Pages 设置页会显示网站地址。

工作流按分支执行：

- 合并到 `dev`：运行 `npm test`，不构建或发布 Pages。
- 合并到 `main`：先运行 `npm test`；通过后运行 `npm run build`，成功后发布 `dist/`。测试或构建失败均不会发布。
- 使用分支 `push` 事件覆盖普通合并、Squash 和 Rebase；直接推送到这两个分支也会触发对应流程。其他分支与标签不自动触发。
- 手动运行时，只有选择 `main` 才会构建和发布；选择其他分支仅运行测试。
- `dev` 与 `main` 的任务互不取消。同一 `dev` 分支的新任务会取消旧测试；`main` 正在执行的发布会完成后再处理后续任务。

Vite 使用相对资源路径 `base: './'`，支持仓库子路径、根路径和自定义域名。本项目没有依赖服务器重写的路由。

参考：[Vite 静态部署文档](https://vite.dev/guide/static-deploy)、[shadcn-vue Vite 安装文档](https://www.shadcn-vue.com/docs/installation/vite)。

## 补充参考图片

把原图放到 `images/original/`，运行 `npm run images:optimize`，脚本会在 `images/` 生成网站使用的图片，无需手动修改图片清单。网站只读取 `images/` 顶层，原图不会打包到 GitHub Pages。停船位置现在使用完整底图上的坐标标记，已取消 `x-x-0` 定位截图。

| 文件名示例   | 含义                                    |
| ------------ | --------------------------------------- |
| `7-3-1.jpeg` | 图 7 泰国，3 号点位，怪物诱饵投放参考位置 1 |
| `7-3-2.jpeg` | 同一点位，怪物诱饵投放参考位置 2            |
| `7-3-3.webp` | 同一点位，怪物诱饵投放参考位置 3            |

- 投饵参考图格式为 `地图编号-点位编号-图片序号.扩展名`；序号必须为正整数。旧的 `x-x-0` 原图仍保留在本地归档，压缩脚本与网站均忽略它们。
- 支持 `jpg`、`jpeg`、`png`、`webp`、`avif` 及全大写扩展名；同一序号保留一张图，避免重复。
- 序号按数字排序（`2` 在 `10` 前）；可有间隔。
- 未确认停船坐标的点位会显示底图和“待确认”提示，不会生成猜测的标记。
- 缩略图可以裁切；主要参考图和放大视图完整展示图片，避免丢失位置线索。
- 图片在构建时自动发现。新增原图后先运行压缩命令，再提交 `images/` 内的生成图片和 `optimization-report.json`，合并到 `main` 后由 Actions 重新发布。CI 测试与构建不依赖原图目录。
- 新增已知地图的新点位时，点位按钮会自动出现；**图片本身不会修改每日轮换数据**。

地图编号：1 天堂岛、2 北美五大湖、3 哥斯达黎加、4 阿拉斯加、5 澳大利亚、6 苏格兰、7 泰国、8 亚马逊。

## 标记停船位置并发布

每张地图使用一张底图，每个 怪物点位保存一个独立的停船参考坐标。目录共 32 个点位；新建标记默认待核对，需要维护者根据游戏实测确认。已保存的位置会直接载入，不会重新初始化，也不会从旧截图猜测位置。

### 1. 准备完整底图

以下文件放在 `images/original/`，再运行 `npm run images:optimize`。文件名与地图的关联由 `src/data/map-catalog.json` 管理。

| 地图         | 原始底图          | 默认点位数 |
| ------------ | ----------------- | ---------: |
| 1 天堂岛     | `paradise.jpg`    |          3 |
| 2 北美五大湖 | `great-lakes.jpg` |          4 |
| 3 哥斯达黎加 | `costa-rica.jpg`  |          3 |
| 4 阿拉斯加   | `alaska.jpg`      |          4 |
| 5 澳大利亚   | `australia.jpg`   |          4 |
| 6 苏格兰     | `scotland.jpg`    |          6 |
| 7 泰国       | `thailand.jpg`    |          4 |
| 8 亚马逊     | `amazon.jpg`      |          4 |

底图也支持 PNG/WebP/AVIF 等扩展名，同一地图只保留一份原图。整图保持原始尺寸与方向比例，标记不是画死在图片里的像素。

### 2. 在工作台落点和核对

1. 运行 `npm run dev`，桌面端点击顶部“标记地图”，手机端从“设置与帮助”进入，或在本地地址后加 `?editor=1`。
2. 选择地图、点位编号。右侧显示该点位的全部投饵实景图，用来对照岸线、岛屿和建筑。
3. 点击“开始标记”，再点击底图放置坐标。默认适应整图；可放大、滚动查看，再落点。拖动滚动不会意外落点。
4. 用 X/Y 百分比微调，可填写会向玩家公开的位置说明。左上为 `(0%, 0%)`，右下为 `(100%, 100%)`，坐标锚点是编号圆圈的中心。
5. 与游戏内实际位置核对后，点击“已核对，确认此位置”。移动坐标或修改说明会自动退回“待核对”。
6. “预览发布效果”只显示已确认的位置；可分批发布，不必等 32 个全部补齐。

玩家端同一张底图显示该地图所有已确认编号，突出当前点位；点击其他编号会同步切换投饵参考图。未确认的点位保留明确提示。

### 3. 保存到项目，再发布

“保存到项目”会写入 `src/data/boat-locations.json`，包含草稿与确认状态。正式界面只展示确认状态且底图版本匹配的标记。保存仅限本地 Vite 开发服务，GitHub Pages 中不提供工作台或写入接口。

```sh
npm test
npm run build
```

检查后提交坐标 JSON；新增或替换底图时一并提交生成图片、`images/optimization-report.json` 与目录配置。合并到 `dev` 后由 GitHub Actions 测试，合并到 `main` 后测试、构建并发布。**保存到项目、导出备份都不会自动推送或发布网站。**

### 草稿、冲突与恢复

- 每次修改自动尝试保存到本浏览器草稿，刷新后可恢复。浏览器存储不可用时会提示，应导出 JSON。此草稿与 Git 中的坐标文件相互独立。
- 每次保存项目文件前，将旧版本备份到 `.local/marker-backups/`（已忽略，不发布）。可从备份导入工作台，检查后重新保存。
- 支持导入 / 导出 `boat-locations.json`；导入仅替换当前工作区，支持撤销，不会立即覆盖项目文件。
- 多标签页或外部修改用文件 SHA-256 校验防止静默覆盖。出现冲突时先导出草稿，再刷新查看项目新版本，必要时按点合并。旧浏览器草稿不会自动覆盖新项目数据。
- 底图绑定的是原图内容 SHA-256。仅改变 AVIF/WebP 编码不会使标记失效；替换或裁切原图后，工作台提示重新核对，可将该地图坐标全部转为草稿再逐一确认。CI 会阻止仍绑定旧底图的坐标发布。
- 数值必须在 `[0, 1]` 内，地图编号与点位必须有效，说明最多 400 字；导入、保存接口和测试共同校验。增加新点位需同时更新目录中的点位数；不改变原有轮换规则。

## 图片压缩方案

默认使用 **AVIF，地图质量 70 / 实景质量 65，4:4:4 色彩采样，effort 6**。保留原始分辨率，不裁切、不缩放，处理方向和 sRGB 色彩后去掉元数据。这是偏重清晰度的有损压缩，不是像素无损；每次始终从原图生成，避免反复压缩积累损失。

基准批次 **47 张投饵参考图 + 8 张共用底图**，合计约 **14.97 MB → 3.90 MB，减少 73.9%**。新增图片后的当前数量和体积以 `images/optimization-report.json` 为准。此前比较过 WebP 无损、近无损、质量 90 与 AVIF 60/65/70，并抽查地图文字、定位标记、船只和岸线。AVIF 65/70 是本批截图在不降低分辨率前提下的选择，不代表任何图片都有唯一最佳参数。

| 样图       |     原始 | WebP Q90 |   采用的 AVIF |
| ---------- | -------: | -------: | ------------: |
| 7-3-2 实景 | 1,758 KB |   232 KB | 121 KB（Q65） |
| 7-3-3 实景 | 1,139 KB |   221 KB | 108 KB（Q65） |

数值使用十进制 KB/MB。无损 WebP 对已有 JPEG 可能更大，例如 `1-1-1` 从 114 KB 增到 578 KB，所以未采用为默认方案。编码参数参考 [Sharp 输出文档](https://sharp.pixelplumbing.com/api-output/)。

```sh
# 新增或更换原图后；内容和参数不变的图片会跳过编码
npm run images:optimize

# 如果需要兼容不支持 AVIF 的旧浏览器，可以整批改为 WebP Q90
npm run images:optimize -- --format=webp
```

脚本保留原图，记录输入/输出 SHA-256 和尺寸；拒绝重复编号、未知冲突文件，压缩后若反而增大则保留较小的源文件。网站的“新窗口查看图片”打开完整分辨率的处理图。删除点位图片时应同时移除该原图及顶层生成图，再运行命令更新报告。

`images/original/` 按现有 `.gitignore` 设置仅保留在本地，不会随 Git 提交，请自行保留备份。干净克隆仍能直接测试、构建和发布，只在重新生成图片时需要原图。

## 手机端使用

实景大图支持点击左右两侧切换上一张 / 下一张，手机端图片下方另有 48px 高的切图按钮；也可横向滑动或使用键盘方向键，首尾循环切换。手机滑动支持较短的拇指动作及轻微斜滑，手指移出图片后仍能完成切换。放大后改为拖动或滚动查看细节，切图箭头与下方按钮保持可用；点百分比恢复整图。竖向滑动、轻微抖动和放大后的平移不会触发切图。单张图片不显示切图按钮，关闭大图后保留当前图片。

手机首页显示紧凑的 8 地图点位总览，点击即进入该地图的参考图。底部始终保留“点位总览 / 切换地图 / 回到今天”：总览保留查询日期，切换地图直接显示该查询日期的参考点位，“回到今天”回到当前参考日期与所选地图的当日结果。

详情页先展示停船地图，按“停船地图 / 投饵实景”切换；地图下可直接进入投饵图。点位和视图切换固定在顶部，多张图片可用缩略图或左右按钮浏览；单图不显示多余的切图条。放大查看后保留当前图片，重复选择同一地图保留点位。日期前后箭头、点位按钮及主要导航均放大以便触控。浅深色模式、中英文和桌面布局继续共用原有数据与主题。

## 点位与刷新规则

`src/lib/schedule.ts` 保留原版的点位数据：以 2025-12-15 为基准，按 26 天周期计算。测试中保存了独立的周期数据快照，用于验证轮换结果；运行、测试和构建均不依赖原版 HTML 文件。

参考结果的更新时间同样沿用原版：北美服 05:00，其他地区服 04:00，均按**用户设备本地时间**计算，不代表服务端绝对时区，也不检测游戏实时刷新。默认依设备时区猜测地区，用户可手动切换，偏好保存在本地浏览器。

“今天”代表当前参考日期，更新时自动跟进；“昨天 / 明天”始终相对此日期，不会重复点击后继续偏移。手动日期查询不随更新跳转。轮换属于社区参考，实际请以游戏内情况为准。

## 主要文件

- `src/App.vue`：查询界面、图鉴、图片查看器和复制操作。
- `src/components/MapEditor.vue`：本地标记、核对、备份和保存工作台。
- `src/components/BoatMap.vue`：共享底图、缩放及比例坐标渲染。
- `src/data/map-catalog.json`、`src/data/boat-locations.json`：地图目录与停船标记数据。
- `scripts/marker-editor-plugin.ts`：仅限本地开发的保存接口、冲突保护与备份。
- `src/lib/schedule.ts`：轮换、日期和刷新逻辑。
- `src/lib/maps.ts`、`src/lib/image-index.ts`：地图编号、图片发现和分类。
- `src/i18n/locales/`：中文文案与英文翻译，包括地图名称。
- `src/components/ui/`：由官方 shadcn-vue CLI 生成的组件，可用 `npx shadcn-vue@latest add ...` 扩展。
- `src/style.css`：主题、响应式布局与无障碍动效偏好。
- `src/mobile.css`：手机总览、底部导航、参考图切换与触控布局。
- `.github/workflows/deploy.yml`：`dev` 自动测试，`main` 测试通过后构建并发布 Pages。
- `tests/`：周期回归、刷新边界、图片覆盖及翻译完整性验证。

## 语言与文案维护

界面支持简体中文与英文，桌面端右上角可随时切换；手机端统一收在右上角“设置与帮助”中。首次访问按浏览器语言选择，不支持的语言回退到简体中文；手动选择保存在 `localStorage` 的 `cotd-language-pref` 中，优先于浏览器语言。禁用本地存储时仍可切换，但不能记住偏好。

切换语言不会改变服务器地区、查询日期、地图或所选点位。页面标题、描述、日期说明、地图名称、图片替代文本、弹窗按钮和复制内容会一起切换。日期输入框的原生日历界面仍由浏览器或系统决定语言。游戏截图保留原图，不翻译图片内文字。

- 优化中文：编辑 `src/i18n/locales/zh-CN.json`。
- 更新英文：编辑 `src/i18n/locales/en.json`，与中文保持相同的键和 `{point}` 等占位符。
- 新增语言：复制语言文件翻译，在 `src/i18n/index.ts` 注册消息，在 `src/i18n/locale.ts` 添加语言选项和浏览器语言匹配规则。菜单从语言选项自动生成。
- 包含数量的英文文案使用 Vue I18n 复数格式，例如 `{count} photo | {count} photos`。
- 修改后运行 `npm test` 和 `npm run build`。测试会检查语言选择、键与占位符一致性、消息编译、英文复数和跨时区日期。

## 外观模式

桌面端右上角外观按钮、手机端“设置与帮助”可选择浅色、深色或跟随系统，默认跟随系统并实时响应系统外观变化。手动选择保存在 `localStorage` 的 `cotd-theme-pref` 中；禁用存储时仍可在当前会话切换。切换外观不影响语言、日期、服务器地区或当前点位。

深色配色覆盖导航、卡片、日期控件、菜单、说明及图片弹窗；参考图片保留原始颜色。`index.html` 在页面绘制前应用外观，避免已选择深色时先闪出浅色页面；`src/lib/theme.ts` 管理运行时偏好，`src/style.css` 中的主题变量统一管理配色。

界面不依赖远程字体、图片 CDN 或后端服务。
